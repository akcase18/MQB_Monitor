# test/

Host-buildable Unity test suites for the logic in [core/](../core/README.md) and [gui/screens/layout.hpp](../gui/screens/README.md) — no hardware, no LVGL rendering. These build and run entirely on the host machine because `core/` and `gui/screens/layout.cpp` have no Arduino/SDL/LVGL-rendering dependency.

```sh
pio test -e simulator
```

Running tests overwrites the simulator environment's build output — run `pio run -e simulator` afterward to restore the interactive simulator binary before using it again.

## Suites

- **`test_core_config/`** — [core/config](../core/config/README.md)'s `ConfigStore` and [core/vehicle](../core/vehicle/README.md)'s `evaluate_warning()`: defaults on blank storage, save/load round-trips (including `display_mode` and partial `save_priority`/`save_signal` writes), falling back to defaults on an unrecognized config version, v6–v9 configs carried across to v10 (the old 16-byte `Settings` head, `brightness_mode` set to Day over v6/v7 padding and kept from v8, `auto_brightness_pct` defaulted; v9 read as a prefix, with `log_source` set to Screen over its padding and an empty log profile), the log profile round-tripping and dropping ids this build doesn't offer or repeats, a panel on a signal this build doesn't offer reset to its default, out-of-range brightness mode and Auto slider loading as their defaults, signal records found again by id after the catalog changes, and leaving a newer firmware's config in place after a rollback until the first save, which then rewrites it whole.
- **`test_core_vehicle/`** — [core/vehicle](../core/vehicle/README.md)'s `SignalStore`, `SignalPoller`, `AutoBrightness` and [core/time](../core/time/README.md)'s `Scheduler`: internal signals (compiled past `SIGNAL_CATALOG_COUNT`, invisible to `signal_catalog_find()`, decoded by the store and polled only when listed), the poller's priority tier (panels keep their full rate while log-only signals share the bus, and a crowded-out background signal is still served past its starvation floor), its stats (sent/answered/timeout/rejection counts, each entry's achieved interval, reset) and flood mode (back to back, with a dead DID still backed off), Auto brightness's mapping (Dim Ctrl clamped to 100 before the slider's ±25% shift, the result capped both ways), ramp, stale-reading fallback, snap while dark and ramp restart, single- and multi-request signal round-trips (a multi-request signal doesn't resolve until *all* its requests report), unit-conversion/display-value correctness, that every catalog entry's `display_min < display_max`, metric↔imperial round-tripping, and that the scheduler actually fires tasks once they're due.
- **`test_gui_layout/`** — [gui/screens](../gui/screens/README.md)'s `compute_layout()` and `compute_prominence_ranks()`: the exact shape of each panel count (1 full-screen, 2 equal columns, 3 hero+stack, 4 even 2×2, 5 matching the legacy fixed layout, 6 even 2×3), that every count's slots fully tile the grid with no gaps/overlaps, that vertical orientation is a true transpose of horizontal (including prominence ranks) for every count except 5 — which gets its own bespoke Vertical shape (a 2×2 of small panels over one wider, higher-priority panel), covered by its own dedicated tests instead — that an out-of-range count gets clamped to 1–6, and that priority rank 0 always resolves to the most prominent slot (hero > large > small) regardless of raw slot index.
- **`test_core_logging/`** — [core/logging](../core/logging/README.md)'s `Logger`: boot recovery on blank storage, on-change dedup (a signal re-polled at the same value produces no new record, even though its `last_update_ms` advanced), the `LOG_MIN_INTERVAL_MS` rate floor in both directions (a signal arriving at half the floor is spaced out to exactly the floor; a slower one is left at its own cadence — both asserted against the constant rather than a literal cadence, so the test survives the floor moving), scoping to the set it's handed (a signal with fresh data that isn't in it never reaches the log; any named set works, repeats and unknown ids ignored), the first fresh value after a signal enters the set always written (so a constant signal appears exactly once) and a stale one never, no records dropped when a 16-signal tick meets the buffer edge, flush triggering, chunk rotation/wraparound (overwriting the oldest slot with newer data), the capture index (each on/off cycle counting as its own log, surviving a reboot, dropping out of the count once the ring laps past it, and self-healing from a corrupt index), lazy chunk creation (repeated boots with the recorder off must evict nothing), `used_bytes()` climbing monotonically to capacity and pinning there once the ring laps, and self-healing recovery when one chunk's header is corrupt/foreign. Chunk sizing is overridden to tiny values via `Logger`'s test-only constructor args — the real ~13MB production budget would make a wraparound test write tens of megabytes per run.

- **`test_core_bench/`** — [core/bench](../THROUGHPUT_TEST_PLAN.md)'s `BenchEngine` (the v4 dash's bench mode). The responder: answers sent at once or after each latency in turn, DID lengths, multi-DID answers in blocks honouring the requester's block size and STmin, multi-frame requests, 0x78 and dropped requests, silence for suppressed tester present and other modules. The tester, closed loop against a responder over a simulated wire: exchange rate at a known latency, 3- and 6-DID reads (single- and multi-frame requests), timeouts, concurrent lanes. And the frame log: both directions stamped, drops counted when full.

- **`test_core_slcan/`** — [core/can](../core/can/README.md)'s SLCAN codec: frame encoding (standard and extended ids, DLC clamped to 8, the timestamp suffix, the longest line fitting `ENCODED_MAX`) and `Session` against a fake `IPort` — the `S6`/`L`/`C` handshake, bitrate changes refused while open, a failed open staying closed, `t`/`T` transmits parsed onto the bus in normal mode but acked-and-swallowed in listen-only or while closed, BELL on every malformed line, and `reset()` closing the channel and restoring defaults.

## Adding a test

Follow an existing suite's shape: a `test_main.cpp` with one `void test_*()` per case, `RUN_TEST()`'d from `main()`/`setup()`. A new suite needs its own subdirectory under `test/` (PlatformIO's Unity runner discovers one binary per subdirectory) — see the two existing `core/` suites for how to construct fakes for `IConfigStore`/`IClock`/`ICanBus` without any real platform.
