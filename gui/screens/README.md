# gui/screens/

Every screen in the app, the panel-layout algorithm, and small helpers shared across screens. Like [gui/widgets](../widgets/README.md), none of this includes `core/` — screens are driven by plain-data view-models and typed callbacks, wired to real vehicle data only by [gui/bindings](../bindings/README.md) and `src/main.cpp`.

## Navigation

```
InfoScreen  ──(swipe down gesture)──>  SettingsScreen ──(Theme row)──────────> ThemePickerScreen
     │                                       │
     │                                       └─(WiFi row)────────────> WirelessSetupScreen
     │
     └─(swipe up)──> LoggingScreen
     │
     └─(host SNIFFREQ + popup Start)──> SnifferScreen ──(Stop)──> InfoScreen
     │
     └─(tap a panel)──> ConfiguratorScreen ──(Signal row)────> SignalPickerScreen
                              │
                              └─(Warning Thresholds row)──> WarningConfigScreen
```

All screens except `InfoScreen` use a top nav bar (title + X close button) over stacked, divider-separated sections; `InfoScreen` itself has no chrome beyond the panel grid, full-screen, aside from a small top-right status glyph (`set_logging_active()` — see below). Navigation callbacks live in `src/main.cpp`, not in the screens themselves — every `DoneCallback`/`PickXCallback` is a plain function pointer the composition root wires up.

## Files

- **`inc/layout.hpp`** / **`src/layout.cpp`** — `compute_layout(count, orientation, out[])`: pure grid-slot placement for 1–6 panels, no LVGL, no `core::`. Each panel count gets its own shape (horizontal orientation):
  - **1** — one full-screen panel.
  - **2** — two equal full-height columns.
  - **3** — a wide hero panel plus two stacked minor panels (not three narrow columns) — the hero/stack width split (`HERO_COLSPAN`/`STACK_COLSPAN`) is a starting ratio pending an on-hardware check.
  - **4** — an even 2×2, all panels equal.
  - **5** — 3 small panels over 2 large ones (the original, legacy fixed layout — the only count that still uses `Theme::Metrics::panel_height_sm_pct/lg_pct` rather than a 50/50 row split).
  - **6** — an even 2×3, all panels equal (small tier).
  
  Vertical orientation transposes whichever shape the count produces (small band ↔ left/right instead of top/bottom) for every count except 5 — a straight transpose of 5's 3-over-2 stacks 3 skinny panels in one column and 2 in the other, which reads poorly on a narrow portrait screen, so 5 gets its own bespoke Vertical shape instead: a 2×2 of small panels over one wider, higher-priority panel. Cheap to unit test — see [test/test_gui_layout](../../test/README.md).

- **`inc/wifi_indicator.hpp`** / **`src/wifi_indicator.cpp`** — `WifiIndicator`, an `LV_SYMBOL_WIFI` in the bottom-left corner while the AP is up: grey while no phone is joined, the accent once one is (the relay's `EVT_AP_STATIONS`). It lives on `lv_layer_top()`, so it shows over every screen and stays put across screen loads; `src/main.cpp`'s `sync_wifi_indicator()` shows and hides it on every AP event, on the 1 s AP check, and after a screen rebuild. Settings' WiFi row and Logging's Erase Logs button reach into the same corner, but neither screen can be open while the AP is up: the Wi-Fi screen's X is the way back to Settings, and it turns the AP off. Not owned by a screen, so `destroy_screens()`/`build_screens()` destroy and re-create it to pick up a new accent.
- **`inc/info_screen.hpp`** / **`src/info_screen.cpp`** — `InfoScreen`, the main dashboard. Places up to `MAX_PANELS` `PanelWidget`s per `compute_layout()`, pulls each one's view-model through a caller-supplied `ViewModelBuilder` callback (so this screen never touches `core::`/`gui/bindings` directly), and fires a `PanelPressCallback` on tap. `rebuild(count, orientation)` re-lays-out and shows/hides panels — call it whenever `Settings::num_panels` changes. Orientation, by contrast, is boot-time-only (see `platform.hpp`'s `DisplayOrientation`): `src/main.cpp` always calls `rebuild()` with the orientation actually active on the physical display, not `core::Settings::orientation`'s possibly-just-staged value, so a Settings change never reflows the grid against a canvas that hasn't physically rotated yet. `refresh()` re-pulls every active panel's view-model, called periodically to keep values live. `set_logging_active(bool)` starts/stops a small blinking red `lv_led` capture indicator in the top-right corner (`LV_OBJ_FLAG_IGNORE_LAYOUT`'d out of the grid it sits over). It replaced a static muted `LV_SYMBOL_SD_CARD` glyph, which was too easy to miss over a dense panel grid — the one thing a "you are recording" cue must not be. The blink is an `lv_anim` on the LED's brightness with `lv_anim_path_step` (a hard on/off, not a fade) rather than an `lv_timer`, so its lifetime is tied to the object: `lv_obj_delete()` deletes a target's animations, meaning a screen rebuild can't leave a timer pointing at freed memory. `InfoScreen` takes a plain bool rather than depending on `core::Logger` (see [core/logging](../../core/logging/README.md)) directly, same reasoning as `ViewModelBuilder`. `set_preview_banner(bool)` shows "Tap screen to exit preview" along the top while a phone is previewing; the grid's top padding grows by the banner's 26 px to make room, rather than the banner covering the top row. Every layout's readouts and gauges still fit at either orientation, the 4-panel landscape gauge most tightly. A tap anywhere on the dashboard, on a panel or not, then goes to the Wi-Fi screen (`main.cpp`'s `info_screen_clicked_cb` and `divert_to_wireless_if_previewing()`).

- **`inc/configurator_screen.hpp`** / **`src/configurator_screen.cpp`** — `ConfiguratorScreen`, opened by tapping a panel. Sections: Signal (tappable row → `SignalPickerScreen`), Units (Imperial/Metric 2-segment matrix), Display (Digital/Bar/Gauge 3-segment matrix), Warning Thresholds (tappable row → `WarningConfigScreen`). Signal and Warning Thresholds hand off to dedicated screens rather than embedding pickers inline — an embedded roller here originally came out taller than expected and spilled into the section below it.

- **`inc/signal_picker_screen.hpp`** / **`src/signal_picker_screen.cpp`** — `SignalPickerScreen`, a full-screen `lv_roller` over every catalog signal. Exists as its own screen (rather than living inline on `ConfiguratorScreen`) because `lv_roller_set_visible_row_count()`'s auto-sizing reserves extra height beyond N literal rows for the partial-row fade effect, which didn't fit alongside the rest of the Configurator's layout.

- **`inc/warning_config_screen.hpp`** / **`src/warning_config_screen.cpp`** — `WarningConfigScreen`, the low/high threshold editor for one signal — toggle each bound on/off, adjust with +/- buttons (tap-to-step, hold-to-repeat) bounded by that signal's `SignalSpec::display_min/max`. Actually wired to persistence (via `DoneCallback` → [gui/bindings](../bindings/README.md)'s `apply_warning_change`) — the original version of this screen had a dead Done button that never saved anything.

- **`inc/settings_screen.hpp`** / **`src/settings_screen.cpp`** — `SettingsScreen`: a Brightness section (one slider, 5%-stepped, editing whichever of day/night the adjacent Day/Night toggle button currently selects — day and night are rarely tuned side by side, so one slider covers both rather than showing two), a Panels section (1–6 count picker), and compact rows — Theme (hands off to `ThemePickerScreen`) beside Orientation (hands off to `OrientationScreen`; no value preview, since the screen being the right way up already shows the active layout) as a split row, then WiFi (full width, hands off to `WirelessSetupScreen`). Logging is deliberately *not* here — see `LoggingScreen` below. The Day/Night toggle is a single button whose sun/moon glyph swaps on tap; toggling and every slider move fire `PreviewBrightnessCallback` immediately so a change is visible on the real backlight without waiting for Done — useful mid-drive, not just a setting tuned once and forgotten. Brightness and panel count are reported through `CommitCallback` on *every* exit from the screen — the X button, but also the Theme, Orientation and WiFi hand-offs, since a swatch pick rebuilds every screen from the config store, a layout change restarts the board, and the AP serves the phone whatever the store holds; each would otherwise lose or read back a value the user had already changed on screen. `DoneCallback` fires only on the X, after the commit, and just cues the return to the dashboard. Portrait gets its own layout throughout this screen (label-above-control rows instead of label-beside-control, taller touch targets using the extra vertical room) rather than a shrunk copy of Landscape's. `set_values()` replaces the cached values when the config changes behind the screen's back (a phone-side edit) — without it, the next exit's commit would write the stale ones straight back.

- **`inc/logging_screen.hpp`** / **`src/logging_screen.cpp`** — `LoggingScreen`: one oversized on/off toggle for [core/logging](../../core/logging/README.md)'s recorder, plus four status tiles (captures saved, storage medium, capacity, minutes recorded) and an **Erase Logs** button. Reached by swiping **up** from `InfoScreen`, mirroring the swipe-down that opens `SettingsScreen` — logging isn't a setting you configure once, it's something flipped mid-drive when something interesting starts happening, and burying it under Settings put it three taps away. The toggle is the full row width rather than a control tucked beside a label, since it gets pressed in a moving car. Driven by a POD `LoggingViewModel` like every other screen here — `src/main.cpp` builds it from `core::Logger` and the active `IStorage`, which is also where `platform::StorageMedium` gets translated into the medium string (gui/ has no platform:: dependency). `refresh()` re-pulls it on a timer so the counters advance live during a capture. The status readout is caption-*over*-value tiles rather than caption-left/value-right rows: stacking each pair lets the value use the full cell width (which is what makes the two-number usage figure fit), and it halves the vertical space in Landscape — the tiles sit 2×2 there, and the room that frees is what the Erase button occupies. Portrait keeps them in one column (at 320px wide a 2×2 grid would put the usage figure back in a cell too narrow for it) and has the height to spare.

  **Erase Logs** wipes the store (`core::Logger::erase()`) behind `screen_helpers`' shared `create_confirm_popup()` — the same Cancel/Confirm popup the Orientation screen's layout change sits behind, with its Confirm painted `warn_hi` instead of the accent since this one isn't undoable. `src/main.cpp`'s `logging_erase_cb` stops recording before erasing (which the popup says): leaving it on would have `sample()` open a fresh capture into the store moments after wiping it. The button greys out when no store is mounted, the same way the toggle does. The Used row is `used / total` against the log ring's budget (`CHUNK_COUNT * CHUNK_SIZE_BYTES`), both numbers sharing one unit chosen from the total. Not *remaining*: the ring overwrites rather than filling up, so once it has lapped, used pins at capacity and recording carries on dropping the oldest chunk — a countdown would sit at zero for the life of the device.

- **`inc/orientation_screen.hpp`** / **`src/orientation_screen.cpp`** — `OrientationScreen`, opened from Settings' Orientation row: a Horizontal/Vertical layout matrix and a **Rotate 180°** button. The two apply differently, which is why they're separate controls rather than a four-way picker. Rotate is live — `RotateCallback` fires on tap and `src/main.cpp`'s `orientation_rotate_cb` toggles the active layout's own flag (`Settings::flipped_horizontal`/`flipped_vertical` — each layout remembers its own), blanks the backlight, re-sends the panel's MADCTL and the touch transform (`IDisplay`/`ITouch::set_orientation(orientation, flipped)`), forces a full redraw, and lights the panel again once rendering goes quiet. A 180° turn keeps the resolution, so nothing is rebuilt. A layout change swaps width and height, which the `lv_display_t` and every screen are sized from at boot, so picking the other layout opens a `create_confirm_popup()` first; Confirm fires `LayoutConfirmCallback`, which persists it, sets the one-shot `Settings::open_orientation_on_boot`, and calls `platform_restart()` (backlight off first); the next boot clears that flag and lands back on this screen, with X returning to Settings. Rotate needs no popup — tapping it again undoes it.
- **`inc/theme_picker_screen.hpp`** / **`src/theme_picker_screen.cpp`** — `ThemePickerScreen`: a grid of `gui::ACCENT_PRESETS` swatches. Tapping one fires `DoneCallback` immediately (no separate confirmation step) — there's nothing to review before committing to a color choice.

- **`inc/firmware_update_screen.hpp`** / **`src/firmware_update_screen.cpp`** — `FirmwareUpdateScreen`, the S3 dash's update mode (see [platform/dash_s3](../../platform/dash_s3/README.md#firmware-updates)). It opens once **Start** is tapped on the "Update firmware?" popup that `src/main.cpp` puts up when a phone asks. The screen shows **Waiting for firmware**, then a progress bar while the image is received. Once the image is verified, a `create_confirm_popup()` asks **Install and restart?**. The close (X) button, which leaves update mode, shows only while waiting: mid-upload there's no clean way out, and at Ready the popup's Cancel is the way out. Driven by `FirmwareUpdateViewModel` from `RemoteBinding::build_update_view_model()`; `firmware_update_task` in `main.cpp` keeps it up for as long as update mode lasts.
- **`inc/wireless_setup_screen.hpp`** / **`src/wireless_setup_screen.cpp`** — `WirelessSetupScreen`: brings up the ESP32-C3's Wi-Fi AP so the rest of configuration can happen from a phone browser instead of this touchscreen. Opening the screen activates the AP immediately (no Activate step). Two mutually-exclusive states driven by `WirelessSetupViewModel::phase` (Idle/Activating → spinner; Active → an `lv_qrcode` linking to the config page plus the SSID/URL as text — the AP is deliberately open, no password). `refresh()` re-pulls the phase without changing screens, so the async Activating → Active round trip (and an idle-timeout auto-deactivation) show up live while the screen is open — see [gui/bindings](../bindings/README.md)'s `RemoteBinding`. The close (X) button is the only way out and deactivates the AP on the way, optimistically rather than waiting to watch the state machine settle — there's no separate Turn Off control. Closing it also ends the phone's preview session, throwing away anything previewed but never saved. While the phone's page is open the dashboard shows its config and sample values, and a tap or swipe on the dashboard comes back here instead of opening a local editor — a local save would otherwise quietly persist the phone's unsaved edits.

- **`inc/sniffer_screen.hpp`** / **`src/sniffer_screen.cpp`** — `SnifferScreen`: what the panel shows while the dash is the USB CAN sniffer for [tools/monitor](../../tools/monitor/README.md) — channel state (Waiting / Listen-only / Normal), frames/s, total, dropped (in `warn_hi` once nonzero — the capture has gaps), and one full-width **STOP**. No X close button; Stop is the only way out from the panel. Unlike every other screen it isn't built at boot: `create()`/`destroy()` bracket each sniffer session, so it costs no LVGL memory the rest of the time. Reached only from `src/main.cpp`'s sniffer mode, after the host's request is confirmed on a `create_confirm_popup()`. Same tile layout as `LoggingScreen` (2×2 Landscape, one column Portrait).

- **`inc/screen_helpers.hpp`** / **`src/screen_helpers.cpp`** — shared pieces every screen uses: `create_screen()` (a full-size, theme-backgrounded top-level screen object), `create_close_button()` (the top-right X every screen but `InfoScreen` uses to exit, freeing the rest of the screen for a nav bar over stacked sections — currently used by all six of Configurator/SignalPicker/WarningConfig/Settings/ThemePicker/Orientation), `create_divider()` (a full-width horizontal rule separating stacked sections), `create_nav_title()` (the top-left title label paired with that close button), `create_list_row()` (a tappable label-plus-chevron row — Configurator's Signal/Warning Thresholds, Settings' Theme/Orientation/WiFi), `style_flat_matrix()` (the flat, bordered, accent-on-checked restyling of a checkable `lv_buttonmatrix`, shared by Configurator's Units/Mode matrices and Settings' panel-count matrix), and `create_confirm_popup()` (a modal Cancel/Confirm `lv_msgbox` in this app's flat dark styling, with a tappable-sized footer — used by the two changes that shouldn't happen on one stray press: OrientationScreen's layout change and Logging's Erase — plus `src/main.cpp`'s sniffer-mode request), and `create_status_tile()` (a caption-over-value readout tile, shared by `LoggingScreen` and `SnifferScreen`).
- **`inc/screen_transition.hpp`** / **`src/screen_transition.cpp`** — `slide_screen_in()`, the drop-in for `lv_screen_load_anim(OVER_*)` that Settings and Logging open/close with. With `GUI_SNAPSHOT_TRANSITIONS` (env:dash_s3, env:simulator) it snapshots the incoming screen once and slides that image over the outgoing one, loaded with invalidation off so the old screen is never re-rendered; each frame is then a pixel copy rather than a full widget render (12 frames per 220 ms slide on the S3, against 7–8). Without the flag, or if the ~300 KB snapshot can't be allocated, it is plain `lv_screen_load_anim()`.

## Adding a new screen

Follow an existing screen's shape: a `class` owning its own `lv_obj_t *screen_`, an `init()` that builds it once against a `Theme` and a set of typed callbacks, an `open()` if it needs per-open state, and `static` LVGL event handlers that dispatch to instance methods via `lv_event_get_user_data()`. Wire it into `src/main.cpp`'s `Composition` struct, `build_screens()`/`destroy_screens()`, and whatever triggers navigation to it.
